## 3.1（4）真机问题追修

用户反馈 3.0 仍然无法打开目录，因此前次模拟器通过不能作为真机问题已解决的结论。
前次用例选择的是 CodexPad 自己的 Documents 子目录，没有覆盖跨 App 的 security scope。

本次确认并修正以下代码缺陷：

- 选择回调仍同步执行 `startAccessingSecurityScopedResource`，加载状态虽设置但主线程可能无法绘制。
  现在保留原始 URL，在选择器的实际关闭回调后，交由独立 I/O 队列获取权限。
- 旧超时只设置取消标志，然后继续等待 `job.value`。系统调用不配合取消时不会真正结束等待。
  现在用单次完成的 continuation，在超时/取消时及时返回；后台工作者保留授权直至真正退出，
  迟到结果不会再次恢复 continuation 或覆盖新项目，排队中已取消的写操作不会执行。
- 旧初始化在 `NSFileCoordinator` 之前解析路径并 `open` 根目录。
  现在先协调原始提供器 URL，再使用协调回调返回的 URL 固定根描述符，仍然保留防逃逸检查。
- 浏览目录使用 `.withoutChanges`，不要求其他文档 App 先保存内容；正文读取和写入仍保持原有协调。
- `readdir` 失败不再被误认为空目录。无授权、协调失败、超时均显示并保留中文错误。
- 设置新增版本与打开阶段诊断；记录不包含 API Key、项目文件内容或完整目录路径。

新增不可取消工作者的超时、取消、排队任务失效及项目切换回归测试。
UI 测试由独立的“授权测试源”App 提供目录，必须通过系统选择器完成跨 App 授权、写入，
并在进程重启后通过书签恢复；没有提供器时直接失败，不再跳过。
测试辅助 App 不作为生产 App 的依赖，不包含在 IPA 中。

这些修复针对可证实的代码缺陷。用户设备究竟停在系统回调、权限申请还是提供器协调阶段，
仍需结合新版打开记录确认，不声称已连接用户真机复现。

## 文件夹无反应的实际代码缺陷

旧版选择器使用 `.folder` 和 `asCopy: false`，`didPickDocumentsAt` 存在；
不能仅凭症状归咎于 delegate 没有连接。其后续处理链存在以下确定缺陷：

1. `WorkspaceStore.attach` 在 MainActor 上调用 `bookmarkData`，加载状态要到之后的
   `refreshTree` 才设置。文件提供器卡在书签/元数据访问时，用户看不到任何响应。
2. 启动时同步解析书签，失败后直接移除记录，既不显示错误也不提供重授权状态。
3. 全量递归扫描最多 20 层，等待所有子目录完成才显示文件树；单个不可用目录可使整个加载失败。
4. 更换目录前先释放旧 scope，却没有确保旧文件任务结束；旧任务只比较根 URL，无法区分
   同一路径的新旧会话。异步 Agent 操作又在执行时取当前根目录，存在跨项目风险。
5. 取消文件选择器没有 completion，presentation 状态没有主动收敛。

修复：选择回调先建立可见加载状态，轻量获取 scope；会话强持有授权并由后台操作持有会话；
书签与文件 I/O 在 detached task 中执行。根目录一级加载成功就显示，子目录按需读取。
任务 generation 和 session UUID 阻止旧结果发布。恢复失败保留证据，显示明确错误及重新授权按钮。
协调操作带取消令牌和超时，不用延时/假刷新修复打开行为。

以上是源码可证实的根因链，不冒充已在用户原 iPad/iCloud 账号上复现。

## 主动发现并修复

- 根路径 `""`/`.` 可进入删除、移动或写入路径：统一禁止根目录变更。
- 悬空符号链接被 `fileExists` 误判为不存在：改用描述符相对操作、`fstatat` 和 `O_NOFOLLOW`。
- 检查后路径被替换：固定授权根目录描述符，逐层打开目录，拒绝链接；协调入口校验根身份。
- 原子创建二次检查竞争：使用 `RENAME_EXCL`，不覆盖外部新建文件。
- 审查后文件变动和编辑器保存覆盖：保存原始内容摘要，落盘前再次核对。
- 固定根描述符的共享枚举游标：使用独立 `openat(rootFD, ".")`，重复扫描不丢项目。
- 单次只处理第一项工具调用：完整处理所有 call ID，逐项返回成功、失败、拒绝。
- 待审暂停后轮数重新计算：轮数/工具计数跨审查继续累计。
- 取消后旧任务继续发布消息：保持运行状态直至任务真正结束，停止时清理未完成调用。
- 新项目/新 Key 继承旧对话：绑定会话与配置 ID，切换保护和对话清理。
- 未验证 fallback 被保存、缓存永不过期：实际工具调用验证与凭据隔离缓存。
- Keychain 先删除再添加：改为优先更新，更新失败不先破坏旧 Key。
- API 错误回显可能含 Key/英文 HTML：不显示服务端原始错误正文。
- 保存中可切换文件、Agent 应用中可编辑：统一 busy 状态与编辑保护。
- 文件被删除后编辑器仍展示旧文件：无未保存修改时清空；有本地修改时保留并警告。
- Diff 忽略末尾换行变化：显式展示末尾换行差异。
